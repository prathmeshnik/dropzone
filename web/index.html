        How it works

        1. SplitYour browser cuts the file into small pieces and sends them as separate requests, so no single request approaches a proxy’s body limit.
        2. SendA couple of pieces go at once. A piece that fails is retried on its own instead of restarting the file.
        3. VerifyThe server checks the total size and computes a SHA-256 before publishing anything.
        4. Keep the linkProgress is tracked per piece, so a dropped connection, a reload, or a backgrounded tab costs you nothing.

        Worth knowing

        • One shared key protects everything. There are no per-user accounts, and anyone holding the key can read every stored file.
        • Files are written to a plain directory and kept until you delete them. No scanning, no expiry, no versioning.
        • Partial uploads are reaped after 6 hours of inactivity.
        • Sessions live in memory, so a restart abandons in-flight uploads. Finished files are untouched.
        • Downloads are forced to attachment unless the type is an image, video, audio or PDF, so an uploaded .html cannot run on this origin.
        • Meant to sit behind a tunnel or reverse proxy that terminates TLS. Bound to loopback by default.
